# Enterprise Control Evidence Matrix

This file maps controls to evidence generated by normal operation. It is not a certification statement.

| Control | Software / configuration | Operating evidence | Owner / cadence |
| --- | --- | --- | --- |
| Authentication | OIDC Authorization Code + PKCE, signed ID-token verification, encrypted HttpOnly sessions | IdP configuration, auth audit events, quarterly access review | Security / quarterly |
| Tenant isolation | Snowflake tenant roles + row-access policy + API tenant context | automated cross-tenant tests, role mapping export, annual penetration test | Security + Data / release + annual |
| Source access | `source_document_access_allowed`, source-reference endpoint, pre-retrieval Cortex filters | denied/allowed source-read audit samples, retrieval regression results | Security + Data / release |
| Upload security | direct multipart, quarantine prefix, magic-byte validation, scanner gate, SHA-256, KMS | scanner results, artifact hashes, quarantine events, object-store configuration | Engineering / continuous |
| Secure development | protected review process, CI, CodeQL, Dependabot, secret scan | successful checks, vulnerability remediation tickets | Engineering + Security / change |
| Review quality | append-only review events, material publication gate | review-event samples, unresolved exception report, quality regression set | Data Operations / cycle |
| Lineage | source reference → observation → snapshot IDs | automated lineage completeness query and sample drill-through | Data Governance / continuous |
| AI safety | deterministic semantic tool, tenant-filtered retrieval, untrusted-source prompt boundary | research evaluation results, citation resolution, injection regression tests | AI + Security / release |
| Audit | tenant-scoped audit event table | quarterly audit-event completeness sample | Security / quarterly |
| Retention/deletion | object lifecycle + admin deletion workflow | deletion requests with completion/residual-retention evidence | Data Governance / request + annual |
| Backup/DR | versioned/object-locked source, migrations, restore runbook | quarterly restore exercise with actual RPO/RTO | SRE / quarterly |
| Reliability | request IDs, durable jobs, SLO definitions | alert tests, SLO dashboard, incident records | SRE / continuous |
| Exports | server-generated export, checksum, short-lived signed URL, manifest | export event and manifest/checksum samples | Engineering / continuous |
| Vendor/subprocessor | configuration inventory and model/storage providers | security review and contract/subprocessor register | Security/Legal / onboarding + annual |

## Evidence rules
- Evidence must include environment and UTC timestamp where relevant.
- Never attach raw customer source text unless necessary and the evidence store is entitled for it.
- A failed control creates a remediation item with owner and target date.
- Evidence is only “passing” when it came from an actually executed control. A configuration file alone is design evidence, not operating evidence.
- CI should generate machine-readable readiness/test artifacts; production restore, alert and access-review exercises are recorded separately because they cannot be proven by source code.

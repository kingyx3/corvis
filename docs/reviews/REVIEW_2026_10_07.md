### Confirmed findings

Migration `004_session_activity_expiry_revocation.sql` atomically preserves revocation for purged human sessions expired under the current policy, while retaining existing revocation provenance, bounded batches, row locking, grants/RLS and cleanup without timeout limits. The authoritative membership lookup rejects the old session on interactive and background requests. A new session ID is unaffected.
- **P2 unauthenticated request buffering:** back-channel logout used `request.text()` before checking 16 KiB, counting characters instead of bytes. The endpoint now uses the shared bounded reader before parsing or database/key work. Regression tests prove early refusal for declared, missing and understated lengths, stream cancellation at the limit, multibyte padding, and unchanged handling of ordinary stream failures. Oversize forms retain the uniform `400 invalid_request` response.
- **Documentation:** the tenant administration guide described expired-session revival as acceptable housekeeping and still said raw-fetch screens could not show policy-specific expiry reasons. Corrected both contracts and documented the streaming limit. Confluence security requirements, workspace story F7 and the engineering review record are reconciled to the final merged evidence.

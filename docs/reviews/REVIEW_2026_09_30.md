## Verified findings and fixes

| Priority | Finding and reproduction | Fix and regression evidence |
| --- | --- | --- |
| P1 security | After the JWKS cache expires, an IdP outage leaves old signing keys trusted indefinitely. A still-valid token signed with the cached key authenticates at cache expiry + 100 seconds despite refresh failure. | Expired key authority fails closed, including subsequent throttled requests. Unexpired keys remain usable if an unknown-key refresh fails. `src/modules/identity-access/server/sessions/oidc.test.ts` covers both outcomes. IdP-unavailable telemetry also classifies the expired-cache refusal. |
| P1 security | SCIM caches a successful token, an attacker exhausts the tenant failure budget, and the token is then rotated/disabled. The old cached configuration still authenticates during lockout without consulting current authority. | Cached verification exempts a recently verified token from the tenant throttle only; every accepted request rechecks Postgres. Revoked tokens are evicted. Existing per-client limits and the bounded cache remain. `src/modules/identity-access/server/directory/scim-security.test.ts` covers revocation during lockout and continued legitimate IdP access. |
| P1 security | Research pins check citation rights and result digests but do not reauthorize the recorded query's fund/document scope. An uncited computed answer remains readable after rights are revoked; a query from a broader same-tenant scope can also be pinned. | Pin creation and listing both intersect the server-recorded query scope with current fund/document entitlements. Listing also checks computed-row digests. Missing, malformed or incomplete scopes fail closed. Lookups are batched and remain tenant-scoped. `src/modules/research/server/research-pins.test.ts` covers retained access, revoked funds/documents, malformed scopes and incorrect digests. |
| P2 reliability | Sequential unauthenticated requests during a cold-start JWKS failure each trigger another provider request because refresh throttling depends on already having cached keys. | Throttle failed cold starts too; concurrent requests still share the in-flight refresh. Reproduced five fetches for five requests before the fix, one afterward. |
| P2 accessibility | Dismissing a discard prompt focuses the dialog container. Shift+Tab then escapes to background controls because the focus trap only recognizes its first/last child controls. | Treat container/non-control focus as a tab boundary. `e2e/notification-settings.spec.ts` exercises Tab and Shift+Tab after dismissing the prompt, including the mobile matrix. |
| P2 accessibility | Analytics selectors inherit muted label text; a browser loading-to-enabled transition produced a reproducible 3.08:1 contrast failure in the existing axe gate. | Use the primary text token for selectable values. Repeat the analytics accessibility gate on desktop/mobile and both themes. |
| P2 documentation | Technical identity documentation describes mandatory broker assertions and unfinished direct IdP/membership verification despite those paths existing in current code. | Correct `ENTERPRISE_IMPLEMENTATION.md` and `SECURITY_ACCEPTANCE.md` to describe direct OIDC, optional broker assertions and independent Postgres authorization, while retaining live evidence requirements. |
| P2 validation | The upload/publish browser test hard-codes Q3 2026, while demo uploads use the current UTC quarter. CI failed at the October quarter boundary despite successful publication. | Capture the selected fund/period before publication and require that exact scope with the incremented version afterward, preserving the intended regression across calendar changes. |

The new security and browser regressions were run against the previous behavior and failed before the fixes. `db/postgres/tests/authorization-cache-revocation.mjs` also verifies real database scope and SCIM revocation in a rolled-back transaction, and runs in the existing Postgres CI acceptance job.

## Validation and operational impact

The PR must pass `npm run verify`, desktop/mobile Chromium E2E, production CSP and non-demo smoke checks, dependency audit, the public artifact guard and required GitHub checks. The linked PR is the source for final check results; no deployed provider or production-data testing is claimed here.

No schema migration or environment change is needed. Old research pins whose query log lacks a provable scope/digest are hidden; asking again creates a verifiable answer. Revoking any resource in a recorded query scope hides the complete answer conservatively. Expired JWKS during an IdP outage now rejects sign-in/API authentication until refresh recovers, deliberately preserving the identity trust boundary. SCIM's known-token path performs one authoritative lookup even during lockout.
